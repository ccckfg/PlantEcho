# 04_整体架构

[过渡] 有了宏观的设计哲学指引，如何保证这套系统的高可用与工程落地呢？接下来，请看我们的系统整体架构拓扑。

我们的系统采用「硬件物理感知 + 云端思考中枢 + 终端情感展现」三层深度互联架构。底端的 ESP32 进行毫秒级的高频传感捕获；通过低开销的 MQTT readings 主题上报至 Fastify 后端；后端不仅负责数据持久化，更集成了 sqlite-vec 向量记忆系统；最顶层则是 Tauri v2 客户端，通过 sync-SSE 实时变更长连接通道，达成多端数据的静默、增量高一致性实时同步。

要点：① 介绍硬件、云端与多终端三层物联拓扑结构；② 阐明 MQTT 与 HTTP 并行的双通信机制；③ 解释 SQLite sync-SSE 增量同步对前端体验的支撑。
时长：1.5 分钟

# 05_硬件端感知

[过渡] 接下来，我们逐层剖析。首先来看我们投入了大量心血、从零摸索的硬件物理感知端。

我们的 ESP32 核心板卡挂载了多路高精度传感器总线。包括用于获取土壤湿度的电容式传感器，用于获取空气温湿度的瑞士 SHT40 芯片，以及用于环境光照的 BH1750。固件内部，我们开发了秒级高频 MQTT 主动推流，将环境指标打包为标准的 JSON 载荷。[停顿] 同时为了让普通用户免于繁琐的代码烧录，我们实现了长按 BOOT 键 3 秒进入 SoftAP 小白配网热点的流程，极大地降低了门槛。

要点：① 介绍土壤、温湿度与光照多源传感器接入；② 解释固件内部 JSON 打包与 MQTT readings 主题通信；③ 介绍 SoftAP 零门槛网页配网机制。
时长：1.5 分钟

# 06_固件弹性与OTA

[过渡] 作为一款物理物联设备，如何在复杂的外部网络环境下保证其生命的弹性与稳定性？我们设计了强悍的固件自我守护防线。

在配网成功后，后端会通过 MQTT config 主题自动下发该设备的专属 API Key 鉴权密钥，并被 ESP32 自动下写写入 NVS 芯片持久区。不仅如此，系统具备了全自动的 OTA 在线无感更新机制。通过在云端宣告 JSON 格式的 manifest 宣告版本，固件会自动下载 bin 文件、在硬件端执行 MD5 完整性校验，并利用 ESP32 的双 OTA 备份分区进行热切换，哪怕断电重启也能在备用区失败回滚，绝不变砖。

要点：① 讲解设备认领密钥自动下发与 NVS 持久化保护；② 详细解构 OTA manifest 校验与空中 MD5 防护；③ 介绍双分区热备份与失败回滚的安全高可用防线。
时长：1.5 分钟

# 07_服务端中枢

[过渡] 穿过硬件层的物理感知，我们来到了系统的核心——云端大脑层。这也是我们全栈交付中完成度达 90% 的云中枢。

我们选用了基于 Node.js 与 TypeScript 的 Fastify 高并发框架，内置严格的 Zod Schema 输入模式校验，确保鉴权安全性。在数据存储上，我们采用了极轻量的嵌入式 SQLite 数据库，并创新性地开启了 WAL 模式，达成超高强度的多线程读写并行。同时，基于 SQLite 的 sync_events 审计表配合 Server-Sent Events (SSE) 实时长连接流，实现了数据的高效、增量、实时反向推送。

要点：① 介绍 TypeScript + Fastify 高并发模块化分层后端；② 阐述 SQLite 数据库 WAL 模式对硬件高频推流的读写性能加持；③ 介绍基于 sync_events 与 SSE 的长连接增量同步。
时长：1.5 分钟

# 08_记忆系统

[过渡] 在解决了数据存储与同步后，我们迎来了本项目的最大亮点与核心创新——植物长期记忆系统的降维落地。

我们自主实现了参考 AgentGal 生命周期模型的长期记忆循环。读数和对话首先作为 Drafts 草稿被快速记录；后台异步 Consolidation 任务定时唤醒，将数据提炼为具有前因后果的 Episode 生命片段（如：“主人为干枯的我浇了一次水”）；随后，利用嵌入式向量 sqlite-vec 库进行向量化，结合 BM25 进行 Hybrid 混合检索；最终引入 Reranker 精准重排，永久沉淀为植物底层的 Understanding 认知世界。

要点：① 介绍参考 AgentGal 模型的 Drafts -> Consolidation -> Episode -> Understanding 记忆流动生命周期；② 详细解构 sqlite-vec 本地向量混合检索对大模型幻觉的阻断；③ 解释 Reranker 对检索精度的 100% 优化。
时长：2.0 分钟

# 09_主动发言引擎

我们为植物设计了“主动发言 Engine”与“和风天气代理”。当后台监听到严重缺水、降温，或者通过 QWeather 天气 API 监测到即将降雨时，Engine 会自动产生事件事实。经过严苛的发言冷却保护锁过滤后，大模型会结合植物的主观 Episode 长期记忆，润色为极具情感、调皮而真诚的人文视角第一人称问候。[停顿] 比如右侧展示的雨前俏皮提醒，让枯燥的数据变成了充满爱的情感共鸣。

要点：① 介绍监听严重读数与天气降雨预警的主动发言引擎；② 解释发言冷却阀门对用户打扰的规避；③ 对比物理阈值警报与 LLM 人文视角润色后的巨大情感体验跨越。
