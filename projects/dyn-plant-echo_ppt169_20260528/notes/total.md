# 02_项目愿景

[过渡] 那么，为什么我们要做 PlantEcho？

市面上的植物监控系统，大多是一个冷冰冰的传感器看板——"水分: 23%"、"温度: 24°C"。但植物不是数据，它们是生命。

[停顿]

我们提出了五个设计原则：说人话、尊重节奏、操作信任、共情细节、呼吸感动效。这五个原则贯穿了整个项目的设计和开发。

要点：① 不是传感器看板而是陪伴 ② 五大设计原则 ③ 设计哲学来源
时长：1.5分钟

# 03_设计哲学：人文关怀

[过渡] 让我用几个具体的例子来说明这些原则。

"说人话"是什么意思？当土壤湿度是23%时，我们不会显示"水分: 23%"，而是显示"我有点渴了·23%"。这就是植物视角的语言。

"尊重节奏"——植物是慢的载体，我们的软件也是。关键操作走5秒撤销toast，而不是突然弹出的确认框。动画全部是380ms缓动，不做突然出现。

[互动] 大家有没有遇到过那种点了按钮没反应的情况？我们在设计中明确要求：未实现的按钮不放出来。

要点：① 具体设计原则示例 ② 反模式避免 ③ 人文关怀落地
时长：2分钟

# 04_系统全景架构

[过渡] 了解了设计哲学，让我们看看系统是怎么实现的。

整个系统分为三层：硬件层、服务端层和客户端层。

硬件层是 ESP32，负责采集传感器数据，通过 MQTT 协议上报到服务端。服务端是 Node.js + TypeScript + Fastify + SQLite 的技术栈，承载了8个核心模块。客户端是 Tauri v2 + React 18 的桌面应用。

[停顿] 数据通过 SSE 实时同步到客户端，用户在任何一端的操作都能实时反映到其他端。

要点：① 三层架构 ② 技术栈选择 ③ 数据流方向
时长：1.5分钟

# 05_硬件层：ESP32 智能感知

[过渡] 先看硬件层。

ESP32 是我们的核心控制器，挂载了四个传感器：SHT40 温湿度传感器、BH1750 光照传感器、电容式土壤湿度传感器和 OLED 显示屏。

它有三个核心能力：SoftAP 配网——长按 BOOT 键3秒就能进入配网模式；MQTT 上报——1秒级的数据上报频率，断线自动重连；OTA 在线更新——通过 manifest 文件就能远程升级固件。

[停顿] 特别值得一提的是，认领设备后，设备密钥可以通过 MQTT 自动下发，不需要用户手动填写。

要点：① 四个传感器 ② 三大核心能力 ③ 自动密钥下发
时长：1.5分钟

# 06_服务端架构

[过渡] 接下来看服务端。

技术栈是 Node.js 24 + TypeScript + Fastify，存储用 SQLite，加上 sqlite-vec 做向量检索，Zod 做 schema 校验。

我们有8个核心模块：设备管理、植物档案、聊天引擎、记忆系统、主动发言、实时同步、天气服务和访问鉴权。

[停顿] 每个模块都是独立的，但又通过事件系统紧密协作。比如传感器数据上报后，会触发设备管理模块更新状态，同时触发主动发言模块判断是否需要提醒用户。

要点：① 技术栈 ② 8个核心模块 ③ 模块间协作
时长：2分钟

---

# 07_记忆系统：AgentGal 生命周期

[过渡] 服务端最核心的模块是记忆系统。

我们借鉴了 AgentGal 的上下文管理，设计了四阶段的记忆生命周期：Drafts → Consolidation → Episode → Understanding。

用户消息和传感器事件先进入 Drafts，然后通过 background_jobs 调度 Consolidation，由 closure detector 判断是否形成一个完整的 Episode，最终从多个 Episode 中提炼出长期的 Understanding。

[停顿] 检索管线也很有意思：我们用 FTS5/BM25 做全文检索，sqlite-vec 做向量检索，然后通过 Hybrid Fusion 融合，还可以加上 Qwen3-Reranker-8B 做重排序。

最终排序公式是：relevance × 0.50 + recency × 0.20 + importance × 0.30。

要点：① 四阶段生命周期 ② 混合检索管线 ③ 排序公式
时长：2.5分钟

# 08_记忆召回与引用策略

[过渡] 有了记忆系统，还需要聪明的引用策略。

我们的核心原则是：诚实优先。

当用户问状态/读数类问题时，优先回答当前传感器数据，不主动引用旧记忆。当用户明确问"记得/上次"时，才允许引用中高相关记忆。高相关记忆最多引用1条。

[停顿] 最重要的是：没有可靠记忆时，禁止说"我记得"。这比引用错误的记忆更伤害用户信任。

要点：① 智能引用策略 ② 诚实优先原则 ③ 引用格式
时长：1.5分钟

# 09_主动发言引擎

[过渡] 记忆系统让植物能"记住"，主动发言引擎让植物能"开口"。

我们有三种触发机制：传感器异常（缺水优先）、天气提醒（下雨提醒带伞）、用户自定义提醒（"十分钟后提醒我浇水"）。

[停顿] 设计亮点是：事件只决定"该不该说"和"事实是什么"，LLM 只负责把结构化事实润色成植物口吻的一句话。比如"今天外面下雨了，记得带伞哦～我会乖乖待在家里的"。

我们还设计了冷却去重机制，避免1秒级的传感器上报导致重复刷屏。

要点：① 三种触发机制 ② LLM 润色设计 ③ 冷却去重
时长：2分钟

# 10_桌面客户端设计

[过渡] 服务端说完了，让我们看看客户端。

技术栈是 Tauri v2 + React 18 + Vite 5，设计语言是 Verdant Echo——Forest-to-Soil 配色系统，从深森林绿到暖奶油白。

我们有五个核心页面：温室 Dashboard、植物详情、植响对话、成长日记和相册。每个页面都遵循人文关怀五原则。

[停顿] 共享的 UI 组件包括 AppShell、SideNav、Card、Chip、Toast 等，Toast 系统支持 undo action，这是"撤销 > 确认"原则的具体实现。

要点：① 技术栈 ② 设计语言 ③ 五个核心页面
时长：1.5分钟

# 11_温室Dashboard

[过渡] 让我展示一下温室 Dashboard 的设计。

每次进入，用户会看到一个时间感问候——"下午好，欢迎回到你的温室"。根据时辰自动切换：早安、午安、下午好、晚上好。

[停顿] 一键浇水按钮点击后，不会显示"已浇水"这样的系统消息，而是显示一个居中的气泡："📝 你为小绿记录了一次浇水"，带5秒撤销功能。

植物卡片上会显示植物视角的状态标签——"我有点渴了"而不是"土壤湿度低"。底部还有 PlantReflectionFooter，是植物口吻的一句话，比如"今天已经是第15天了，谢谢你一直陪着我"。

要点：① 时间感问候 ② 撤销 toast ③ 植物视角语言
时长：2分钟

# 12_植响对话与成长日记

[过渡] 植响对话是用户和植物交流的核心界面。

左侧是植物档案卡，右侧是对话区。支持流式回复、快捷动作 chip。快捷动作渲染为系统操作 chip，不是伪装成用户消息——这是"操作信任"原则的体现。

[停顿] 成长日记页面有 Bento StatCard 展示统计数据，里程碑时间线记录植物的重要时刻。

里程碑可以被回应——用户悬停里程碑卡片就能直接给植物留言，留言会以系统消息形式发到对话流。"看见"和"被看见"形成闭环。

要点：① 对话界面设计 ② 快捷动作渲染 ③ 里程碑回应机制
时长：2分钟

# 13_技术亮点

[过渡] 让我总结一下项目的技术亮点。

第一个亮点：混合记忆检索。我们的检索系统在120条记忆、48个查询的测试集上，Top-1、Top-3、MRR 均达到100%。

[停顿] 第二个：Qwen3-Reranker-8B 的集成。这是一个可选的 rerank 层，显著提升了排序质量，而且配置可以自动从主 LLM 连接派生。

第三个：OpenAI-compatible API。我们的服务端暴露了标准的 /v1/chat/completions 和 /v1/models 接口，可以被任何 OpenAI 兼容的客户端调用。

第四个：实时同步。通过 SQLite sync_events + SSE 推送，实现多端实时刷新。

第五个：MQTT 自动密钥下发。认领设备后，密钥通过 MQTT config topic 自动下发，不需要用户手动操作。

要点：① 检索准确率 ② Reranker 集成 ③ OpenAI API ④ 实时同步 ⑤ 自动密钥
时长：2.5分钟
